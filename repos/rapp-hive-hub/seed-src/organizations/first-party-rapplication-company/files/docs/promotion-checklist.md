# Public promotion checklist

Default outcome: **blocked until evidenced**. This is a review instrument, not
permission to publish. Release prepares; quality verifies; a separate decider
decides; the owner alone merges the public PR.

## Subject and authority

- [ ] Select the exact candidate and separately reviewed public distribution.
      Never point a projection builder at a private organization or Hive root.
- [ ] Freeze complete relative-path inventories and raw hashes, including the
      intended public payload, dependencies, support, and qualification suite.
- [ ] Recheck actual internal distribution, current-candidate chat dogfood,
      feedback dispositions, and the founder-CEO recommendation.
- [ ] Verify identities/grants through the trusted native host. Confirm the
      verifier is neither a builder nor the CEO, and the decider is neither.
- [ ] Obtain independent verification and a distinct subsequent decision
      referencing exact subject, review, and verification records.

## Nested privacy scan

- [ ] Scan **every** new or changed filename and file's complete content, not
      only a diff or an allowlisted extension. Include PR title/body, comments
      proposed for publication, and generated artifacts.
- [ ] Recursively inspect ZIP, egg, gzip, and tar contents, including nested
      archives, JSON-embedded archives, member names, and decoded content.
      Reject traversal, links, special files, duplicate members, unreadable
      formats, decompression-limit breaches, and unscanned bytes.
- [ ] Normalize plain, JSON-escaped, HTML-escaped, and URL-encoded forms.
      Detect personal names and private project labels from an owner-supplied
      **private runtime denylist**, home paths, LAN hostnames, private and
      link-local addresses, session/operation identifiers, credential prefixes,
      authorization material, and private-key blocks.
- [ ] Keep the denylist, private locations, source observations, raw transcripts,
      keys, native identities, and raw receipts out of the public distribution.
- [ ] Review zero findings against the exact outgoing inventory and PR text.
      A scanner crash, skipped archive, or missing input is not zero findings.
      Record scanner version, limits, file/member counts, and report hash.

## Licenses and truthful claims

- [ ] Check every source, dependency, asset, data sample, and bundled license
      for provenance, redistribution permission, required notices, and conflicts.
      The seed's MIT license does not relicense later third-party additions.
- [ ] Preserve the MIT notice when redistributing these starter files.
- [ ] Separate source tests, structural RAPP/1 checking, real chat observations,
      authenticated acceptance, and publication. Never promote a structural
      pass as identity/signature/grant verification.
- [ ] Do not claim running agents, staffed support, live users, completed
      external effects, or a signed internal channel without actual evidence.

## PR and owner merge

- [ ] Run all applicable local tests and public build checks on the proposed
      head; compare deterministic output hashes from two builds.
- [ ] Review the exact public diff, filenames, generated output, and sanitized
      evidence summary. Obtain owner authorization for that precise proposal.
- [ ] Open a non-draft PR only through existing authorized access. Require all
      configured CI checks on its current head; missing/pending/skipped/failed
      checks block. Never bypass a gate by inventing an exception or signature.
- [ ] Record a ready-PR handoff, not a completed release. Changes to candidate,
      projection, PR text, or head require their affected checks again.
- [ ] The owner reviews and merges the checked head. Observe that actual
      merge and publication afterward, including artifact hash and withdrawal
      procedure; record them separately. No automated merge is authorized.
