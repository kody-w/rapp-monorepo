Why Brainstem

Six reasons a local loop beats a better prompt

Every one of these is a property you can check on your own filesystem in under a minute. That's the point — none of it requires trusting a slide.

01

Determinism, not persuasion

Custom instructions ask a model to behave. Code in the loop makes it behave. Memory injection isn't a suggestion — it's a step that always runs before the model reads a word.

02

Your data has an address

State lives at ~/.brainstem. You can point at it, back it up, diff it, and delete it. "Where is our AI's memory?" gets a filesystem answer — which is the answer compliance actually wants.

03

Nobody can turn it off

Platform features arrive and depart by org policy and preview status. Your loop changes when you change it. No deprecation notice, no waiting on a tenant admin.

04

Memory that doesn't expire

Repo-scoped assistant memory is shared with collaborators and rolls off on a timer. Yours is JSON on disk. It expires when you delete the file — and it works with no repo at all.

05

Same file, three tiers

A storage shim means one agent file runs on your laptop, then on Azure Functions, then in Teams. No rewrite between prototype and production — the exact step where most AI projects die.

06

Same engine, no new keys

The GitHub Copilot CLI is the preferred backend, so the runtime uses the developer tooling you already signed into. No API keys to provision, no second vendor to onboard, no procurement cycle to start.

The bootcamp

Four sessions. You leave with a running agent, not notes.

Everyone builds. Nobody watches slides. If your laptop can run gh auth login, you can finish. Full detail in CURRICULUM.md.

Session 1 · 25 min

Clean machine → living agent

  • One install line, one auth step
  • Brainstem boots; you meet it
  • Introduce yourself, clear the chat, watch it still know you
  • Open ~/.brainstem and look at your own memory in a text editor
Outcome: memory you can point at, on your own disk.
Session 2 · 30 min

Agent surgery

  • Export a live agent to a single file
  • Delete it — watch the agent honestly say it can no longer do that
  • Drag it back in; capability returns, hot-loaded
  • Install @rapp/learn_new from the registry, SHA-256 verified
Outcome: capability is a file you control, not a vendor toggle.
Session 3 · 35 min

Build your own, from plain words

  • Describe an agent in a sentence; the file gets written and hot-loaded
  • Wire it to a real task from your actual job
  • Give it a soul.md identity
  • Break it on purpose, read the error, fix it
Outcome: your agent, doing your work, running on your machine.
Session 4 · 30 min

Ship it: the Copilot Studio hand-off

  • Promote the same file to Tier 2 without a rewrite
  • Map your proven agent onto a Copilot Studio agent
  • Publish to a channel; a colleague uses it in Teams
  • Governance, ownership, and what to hand your admin
Outcome: a published agent your team can actually use.

Before you ask

Fair questions

Do I need to buy anything?

No new keys and no new vendor bill for the runtime — the GitHub Copilot CLI is the preferred backend, so it uses developer tooling you sign into with your existing GitHub account. Whatever GitHub Copilot access your account has is between you and GitHub; we make no claims about your entitlement. Tier 2 and Tier 3 involve your own Azure and Microsoft 365 subscriptions as usual.

Is this a replacement for Copilot Studio?

The opposite. Copilot Studio is the hero destination in Session 4. Brainstem is the on-device launchpad where the agent gets built and proven first, so that what you publish is something you've already watched work.

What if my company blocks local installs?

Start with the browser walkthrough — no server, no Python, no install. It runs the real brainstem UI against an in-browser simulator, so you can complete the entire tour and make the internal case before anyone installs anything.

I'm not a Python developer.

Fine. An agent is one Python file with a docstring and one function that returns a string, and in Session 3 you describe it in plain words and the file gets written for you. People who can read a config file finish this bootcamp.

How is this different from just writing better instructions?

Instructions are a request the model may ignore. A loop is code that runs whether the model likes it or not. Memory injection happens before the model reads a single token, every time. That difference is the entire product.

What does it cost to attend?

Nothing. The material is public, the repo is open, and the sessions are run to grow the ecosystem. Bring a laptop and finish something.
