RAR got a front page — and the only thing that lied all night was a green checkmark

Two asks, one message apart: make RAR the front page of the agentic web, and do not break anything with ANY future change. They pull against each other, so the second one went first. A broken agent URL is invisible to RAR. Those paths live inside other people's brainstems, scripts and products, and a static file returns no telemetry — nobody here would ever learn it broke. So permanence stopped being a guideline and became a gate: an append-only ledger of 319 published paths, checked in CI, proven to fail on rename, on delete, and on a manifest rename. Then the surfaces. A front door with no GitHub in it, because the loudest line in the meeting transcript was that business users do not live in GitHub — driven headlessly against the deployed page with github.com blocked at the route layer, and it never needed it. Nine static endpoints off raw GitHub with no key and no server. Audience segmentation that had a real bug in BOTH directions. And 76 aggregated bookmarks toasted into agents that actually take a subject and return a procedure. Then the part worth staying awake for. The live API served 278 agents at version 1.0.0 while the registry held 279 at 2.0.0, and every workflow reported green the whole time. The rebuild was gated on `event_name == 'push'`, so the one button a maintainer reaches for when the API looks stale rebuilt it and then threw it away. Same shape as episode one: the check was fine, it just could not fail. The front page itself now ranks 279 entries, each row carrying the numbers it was scored on. Its first cut said 355 — because all 76 crawled entries were already hosted agents, so it listed every one of them twice. That correction is in the episode, because a ranking you cannot audit is just an opinion with a number on it.
