The release couldn't be cut — and the health check had been dead for 82 days

A release was requested. Pre-flighting the gates locally first turned up two failures that had nothing to do with the release, and following them led somewhere worse: the nightly health check had failed 84 times in a row, last green on 11 May. The check was broken. Not the thing it checks. Gated agents record _stub_sha256. The integrity audit read _sha256, which is absent on those agents, then formatted its own error message with the missing key and died on a KeyError before it could print why. A second scanner was still banning exec() — a rule the registry had deliberately retired in favour of tagging it as a declared capability. Then the check itself turned out to be incapable of failing. It ran the suite as `pytest … | tee log`, so the pipeline exited with tee's status, which is always zero. The entire suite could be red and nightly would still report green. Its registry rebuild ran on a shallow checkout, so all 279 agents came back stamped with a single commit and today's date — provenance, fabricated. Twelve defects fixed, 14 hermetic tests added to CI, and nightly went green for the first time since May. One decision is left, and it is not a technical one.
