Ten-minute check, after setup.

Installation and sign-in time vary. Start the clock only after the real setup canary succeeds.

  1. InstallUse the generic prompt. A supported operator must resolve the current plugin and complete real POST /chat verification first.
  2. AddChoose one small preference or agent you know well.
  3. AskHave Brainstem use it through the real POST /chat path.
  4. InspectInspect the selected local file yourself. Operator evidence proves lifecycle and canary verification, not the content edit.
  5. DecideKeep it only if it reduced re-explaining or preserved capability.
Pass

The selected preference or agent appears in the real answer, its local file is intact, and the operator verification receipt is valid. This does not prove portability into every X.

Fail

It did not preserve capability or reduce re-explaining. Do not adopt it. Removal is a separate manual action, not a one-click promise on this page.

Setup and integrity

The installed marketplace plugin is the local lifecycle authority. It verifies the reviewed installer bytes, preserves the pre-mutation state, runs the unchanged installer, then requires a later real POST /chat canary before claiming live verification.

The person wants their RAPP Brainstem. Explain the exact mutation briefly, follow the public machine contract, install or resolve the current marketplace plugin, and use that installed bundle as the local trust anchor. Leave the person only unavoidable sign-in or consent. Installation is not verification. Prove the result through the unchanged real POST /chat path. If the required operator path is unsupported, stop instead of improvising.

Boundaries and ownership

Brainstem wraps the unchanged public engine and installer. It is not a second runtime and does not own intelligence. Soul, agents, memory, configuration, credentials, and private lifecycle evidence remain user-owned. Additional context is in scope only when the user explicitly selects or configures it.
